## 2024-05-18 - Icon-Only Button Accessibility
**Learning:** Found several icon-only interactive buttons in `TopBar.jsx` and `UnifiedFeed.jsx` that were lacking both `aria-label` definitions (making them invisible/unclear to screen readers) and `focus-visible` states (making them difficult to track for keyboard navigators). Some buttons were only visible on `group-hover`, making them completely inaccessible via keyboard.
**Action:** When adding or encountering icon-only interactive elements, ensure they have descriptive `aria-label` attributes and implement clear `focus-visible` styling (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary`). If an element is hidden by default and shown on hover, ensure it is also visible on focus (e.g., `focus-visible:opacity-100`).
## 2024-05-24 - Improve form accessibility with autoComplete and aria-describedby
**Learning:** Using `autoComplete` attributes on form fields is critical for assisting users with password managers or browser autofill, reducing cognitive load and friction during sign-up/login flows (WCAG 1.3.5). Additionally, using `aria-describedby` to link input constraints (like "Must be at least 8 characters long") to the related input field ensures screen reader users are aware of the requirements before or while filling out the form, rather than encountering an error after submission.
**Action:** Always include appropriate `autoComplete` attributes (like `name`, `email`, `new-password`, `current-password`) on standard form inputs. Always use `aria-describedby` to programmatically associate helper text or constraints with their corresponding inputs.
## 2024-06-08 - Accessible Icon Buttons and Status Indicators in Dashboard
**Learning:** Found a pattern in dashboard components (`IntegrationsPanel.jsx`) where icon-only buttons lacked `aria-labels` and visual status indicators (like colored dots for "active" or "syncing") were inaccessible to screen readers.
**Action:** Added `aria-label` and `title` to icon-only buttons along with keyboard focus styles (`focus-visible`). For status indicators, added screen-reader-only text (`<span className="sr-only">`) and hid the purely visual elements using `aria-hidden="true"`. Also added a `title` tooltip to the visual status indicator wrapper. Will apply this pattern to other dashboard components with similar visual indicators.
